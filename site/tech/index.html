The model

sintr is an agent pack: a portable skill (the instructions in SKILL.md) plus a filesystem layout of Markdown files. There is no backend, no database, no API and no MCP server. Any agent with file tools can operate it. The agent is the interface; the files are the product.

  1. Youchat or voice
  2. Agentread / write
  3. ~/sintr/*.mdweekly
  4. PDF reportapprove
  5. Therapist

Two languages, on purpose

The pack is written in English: instructions, field keys and examples. In use, the conversation, the values in the ledger and the reports follow the owner's language and words. Keys stay in English so files stay parseable across locales; values stay verbatim so nothing is lost in translation.

Deterministic where possible

Counting is done by a stdlib Python script, not by the model. The model writes prose on top of those facts and is instructed never to invent numbers, emotions or diagnoses. The report's numbers, chart and day-by-day grid are computed by a second script, which also checks every quote against the ledger. Unknown stays unknown.

The ledger

One folder, ~/sintr by default, seeded from templates/sintr/. Monthly logs are append-only, and the files that answer “what is true now?” are edited in place.

Time
Timestamps in UTC ISO 8601, dates as YYYY-MM-DD, reports by ISO week (YYYY-Www). Week ranges are computed in the ledger's timezone.
IDs
entry-YYYY-MM-DD-NNN and checkin-YYYY-MM-DD. Never reused.
Unknowns
Omitted, or written as unknown. Never guessed. Partial entries are valid and can grow later.
Corrections
Fix the live entry and add a dated note in the same file. History is never rewritten silently.
Scales
Emotions 0–100 at the time; check-in ratings out of 5; sleep in hours.

Entries and check-ins

Entries follow the cognitive-behavioral thought record (Beck), adapted for chat. Tier 1 is always captured. Tier 2, the cognitive restructuring, is offered when the owner is steady and never forced; it can be added later with a dated note.

How the agent captures

Receive first
Reflect what was heard in a line or two. No fixing, no reframing yet.
Ask narrowly
One or two questions per message, only for fields that matter and are missing. Never a checklist.
Verbatim
Thoughts in quotes, in the owner's exact words and language. Paraphrase loses the emotional meaning.
Scale, don't editorialize
“From 0 to 100, how strong was that?” rather than “that must have been awful.”
Write, then confirm
Show the entry, correct what the owner flags, then append it at the end of the month file and re-read the tail.

The full rules live in SKILL.md and references/entry-framework.md.

The weekly pipeline

The report is the product surface: the loop week → digest → report → session is what the owner actually experiences. Each step has one owner.

  1. Collect scripts/week_collect.py reads the week's entries and check-ins in the ledger's timezone and prints a Markdown digest: the check-in table with averages, every entry, emotion and tag frequency, and the raw entry blocks. Stdlib only, deterministic, exit 0 even for an empty week.
  2. Draft The agent writes reports/YYYY-Www.md following the weekly report guide: six short sections in plain language, the owner's own words in quotes, dates for every pattern, observations labeled as observations. It types no numbers.
  3. Preview scripts/report_pdf.py --draft prints the report as a PDF marked as a draft, with the numbers, the chart and the grid computed from the check-ins. It looks up every quote in the ledger and warns about anything it cannot find word for word.
  4. Review The owner reads the preview and asks for changes; the agent edits the Markdown and prints again. status: reviewed, then the final PDF.
  5. Approve Only an explicit approval enables sending. require_approval: true is the default in config.md.
  6. Send The PDF the owner read, never the Markdown, through the configured gateway, for example hermes send --to whatsapp:<number> --file reports/2026-W42.pdf.
  7. Record status: sent, sent_to and sent_at are written into the front matter, and nothing else.
$ python3 scripts/week_collect.py --ledger ~/sintr --week this   # or: last, 2026-W42
$ python3 scripts/report_pdf.py --ledger ~/sintr --week 2026-W42 --draft   # preview

What the therapist receives

Page 1, a letter
How the week went, in a few warm lines; the owner's own topics for the session, as an open checklist; and how the report was made and how to read it.
Page 2, the numbers
Averages with their number of days and the week before; mood, anxiety and sleep over the last four weeks as continuous lines, dotted across days without a check-in; the day-by-day grid; the day's own notes.
The moments
Three to five notebook cards in thought-record order: what happened, what went through the owner's mind (verbatim, highlighted), the emotions with their intensity, the body, what they did. Then what repeated, as dated observations, and what helped.
The checks
Every quote is looked up in the ledger and every intensity compared with its entry. Entries marked share: no never appear. The page is printed by a local headless Chrome from a self-contained HTML file (embedded fonts, no requests) and saved with mode 600.
Why this shape
The DBT diary card, the CBT mood check and thought record, and research on what helps clinicians before a session, with sources, in references/report-framework.md.

The fields that change on send are underlined. A quiet week gets a short “quiet week” report; nothing is fabricated to fill it. A full example lives in docs/example-report.pdf, printed from docs/example-report.md, and the writing rules in references/weekly-report-guide.md.

Install

Installing means two things: putting the skill where your agent finds it, and creating the ledger from the templates. Every target also writes ~/.sintr/config (the ledger path), ~/.sintr/sintr.md (a canonical copy of the instructions) and the collector at ~/.sintr/bin/week_collect.py. Nothing runs in the background, and re-installing never overwrites ledger files.

The repository is a self-hosted Claude Code plugin marketplace. From inside Claude Code:

/plugin marketplace add tiagomoraes/sintr
/plugin install sintr@sintr

Claude Code discovers skills/sintr/SKILL.md on its own. To copy the skill to ~/.claude/skills/sintr and create the ledger yourself:

$ git clone https://github.com/tiagomoraes/sintr.git
$ cd sintr
$ ./installers/install.sh claude-code ~/sintr
$ git clone https://github.com/tiagomoraes/sintr.git
$ cd sintr
$ make install-hermes   # or: ./installers/install.sh hermes [ledger-path]
  • copies skills/sintr/ into ${HERMES_HOME:-~/.hermes}/skills/sintr;
  • creates the ledger (default ~/sintr) from templates/sintr/, skipping files that already exist;
  • sets 700 on the ledger directories and 600 on its files.

Verify: load the skill (hermes --skills sintr, or just ask) and send a check-in such as “Mood 4/5, slept 7h.” You should get one short confirmation and a new ## checkin-… block at the end of ~/sintr/checkins/YYYY-MM.md.

OpenCode, OpenClaw, Cowork or your own setup:

$ git clone https://github.com/tiagomoraes/sintr.git
$ cd sintr
$ ./installers/install.sh generic ~/sintr

The skill lands in ~/.sintr/skill/. Then, depending on the agent:

  • Skill-aware agents: point the agent at ~/.sintr/skill/, or copy it into the agent's skills directory. It's a standard SKILL.md pack.
  • Instruction-file agents (AGENTS.md, CLAUDE.md, a custom system prompt): include ~/.sintr/sintr.md or the skill's SKILL.md.
  • GUI agents such as Cowork: zip ~/.sintr/skill/ and upload it as a skill.

Per-agent notes live in installers/snippets/.

First run

  1. Configure Fill ~/sintr/config.md: name, language, timezone, therapist name and contact, session day and time, report_day and report_time. Keep require_approval: true unless you deliberately decide otherwise.
  2. Capture Describe a situation and confirm the structured entry appears in entries/YYYY-MM.md.
  3. Report Ask for the weekly report and review the draft PDF your agent sends you (reports/YYYY-Www.draft.pdf) before you wire any schedule. Printing it needs Google Chrome, Chromium or Edge, found automatically, or Playwright; without one, the script still writes the HTML for you to print from a browser.

To update: git pull and re-run the same install command; skill files are replaced and the ledger is never overwritten. To uninstall: delete the installed skill folder and, if you want, the ledger. Nothing else is touched.

Privacy architecture

The ledger is some of the most sensitive data a person can produce about themselves. These rules are part of the skill, and agents using it are instructed to treat them as non-negotiable.

Storage
A local folder. The installer sets 700 on directories and 600 on files and never relaxes them. No sintr cloud, no sync, no telemetry.
Default deny
Content leaves the ledger only with the owner's explicit approval for that specific share. The therapist is a third party too. require_approval: false pre-authorizes scheduled sends, which are still recorded.
Audit trail
The weekly report goes out as the PDF the owner previewed, so the exact artifact is traceable. sent_to and sent_at go into the report's front matter.
Containment
Ledger content is never copied into group chats, team channels, public notes, shared agent memory or third-party services. Memory, summary or embedding tools must exclude psychological content by default. Beyond the weekly report PDF, screenshots and exports happen only on explicit request.
Deletion
Confirm the scope, delete from the live files, add a dated tombstone only if the owner wants one. No secret copies.
The model boundary
What you say to your agent, and every file it reads to answer you (for example the week's entries when it drafts a report), is sent to the agent's model provider as context, under that provider's data policy. sintr adds no other network path: the installer, the collector and the PDF generator run locally. If that boundary matters to you, run your agent on a model you host yourself.
Git and backups
Optional, and only as a private repository or not at all. Backups are the owner's call; encrypted ones are recommended. An encrypted-at-rest option is on the roadmap.
Clinical limits
No diagnoses, no labels, no treatment or medication advice. On signs of acute risk the agent stops the journaling flow and points to human help: CVV 188 in Brazil, 988 in the US and Canada, 116 123 in the UK and Ireland, or the local emergency number.
Compliance
sintr makes no LGPD, HIPAA or GDPR claims. The architecture simply minimizes exposure: data leaves the owner's machine only through approved shares and the agent's own model calls.

Full rules: references/privacy-and-safety.md.

Scheduling

sintr has no daemon. Run the weekly flow with whatever scheduler your environment already has.

Hermes
An agent-driven cron job scheduled before your session, so it can write the report. For example, Sundays at 20:00 with the prompt: “sintr: generate this week's report from the ledger, save it to reports/, render the draft PDF and send it to me for review. Do not send anything to the therapist without my approval.”
cron, launchd, systemd
Schedule the collector for the digest and let your agent pick it up at your next interaction. Keep the output inside the ledger so it inherits its permissions.
# crontab example: Sundays at 20:00
0 20 * * 0  python3 ~/.sintr/bin/week_collect.py --ledger ~/sintr --week this --out ~/sintr/reports/digest-latest.md

Contributing
Issues and pull requests are welcome on GitHub. Run make validate before opening a pull request.
New agents
Any agent with file tools works today. To add first-class support, add a snippet in installers/snippets/ and, if the agent has a skills directory, a target in installers/install.sh.
The schema
Starter files live in templates/sintr/; the entry framework in skills/sintr/references/entry-framework.md. Add keys rather than renaming them: the collector keeps unknown keys as extras and passes the raw blocks through, but renamed keys stop being parsed.
Roadmap
An encrypted-at-rest option (age or gpg), wearable and sleep import into check-ins, a multi-week trend view in insights/, and a local read-only view for browsing entries.
